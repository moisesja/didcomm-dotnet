**Attachment ids are opaque and unique per mediator. Using one as a key deduces nothing else.**
- 3.0 L170: "The `id` is an opaque value, and the recipient should not deduce any information from it, except that it is unique to the mediator. The recipient can use the `id`s in the `message_id_list` field of `messages-received`."
- 4.0 L257: the same, with "**SHOULD NOT**".
- Hence the key includes the mediator DID (D-3), and ids compare exactly (D-8).

**A message the client does not open is not acknowledged, so it stays queued.**
- 3.0 L145: "Delivered messages **MUST NOT** be deleted until delivery is acknowledged by a messages-received message."
- 4.0 L212: the same.
- 3.0 L177: "After receiving messages, the `recipient` sends an acknowledge message indiciating which messages are safe to clear from the queue."
- 4.0 L268: "After receiving messages, the `recipient` **MUST** send an acknowledge message indiciating which messages are safe to clear from the queue."
- A message held back or failed is not safe to clear, so it is never in `message_id_list`.
- A delivery with nothing safe to clear sends no `messages-received`. That is main's behaviour since #96/#100, and #111 does not change the rule.
- **No conflict** with a client that declines to open a delivered message for a while: the mediator keeps it (L145/L212) and delivers it again.

**Live mode.**
- 4.0 L308: "If _Live Mode_ is active, messages still **MUST** be delivered via a `delivery` message and the `recipient` **MUST** send an acknowledgement message `messages-received`. If a message is not acknowledged, the message **MUST** be added to the queue for later pickup."
- A held-back live push is not acknowledged, so the mediator queues it again.
- 4.0 L304 and 3.0 L203: queued messages "**MUST** still be requested with `delivery-request` messages". So the drain stays the way queued messages arrive.

**Message ids compare ignoring case; attachment ids have no case rule.**
- threading.md L9: an `id` "SHOULD be written in lower case but MUST be compared case-insensitively". The duplicate filter's key already folds the inner message id.
- message_structure.md L174 (attachment `id`) gives "unreserved URI characters" and no case rule.

**The sender key in the outer envelope.**
- encryption.md L119: "the unpacking process on his end resolves the `skid` protected header value using Alice's DID document's `keyAgreement[0]`".
- L140: `apu` "MUST contain the `skid` value base64 RawURL (no padding) encoded".
- L147: "authcrypt implementations MUST be able to resolve the sender kid from the `apu` header if `skid` is not set."
- message_structure.md L23: anoncrypt(authcrypt(plaintext)) "hides the `skid` header in the authcrypt envelope".

  - The client reads the protected header (unauthenticated) only to pick an accounting partition (D-1).

## Invariants (write these first; every bound says what it counts, when it is taken, when it is released)

**Notation:**
- B = `UnpackTimeout` (20 s by default);
- F = max(1 tick, B/4) (5 s);
- τ = (B − F)/25 (0.6 s);
- T0 = 30·B (10 min); Cap = 180·B (1 h);
- C = 64; P_named = 4; P_anon = 16;
- Q = 256 entries per memory partition; R = 256 memory partitions.

### Opening a delivery

**I-1 Container bound (ADV3-2, the pool-thread residual).**
- At most C host unpack calls are started and not yet ended per container (channel).
- Counts: calls being awaited plus calls let go.
- Taken: atomically under `UnpackReservations._gate`, before the host work item exists.
- Released: exactly once, by a continuation on the host task when it completes for any reason (including "never ran, its token was already cancelled"), or directly when the work item is never created.

**I-2 Partition bound (ADV2-2).**
- Per (mediator, mailbox, sender key), host calls started and not ended number at most P: P_named for a named sender, P_anon for the anonymous partition.
- Taken and released with I-1, in the same handle, under the same lock.

**I-3 No late host code (ADV4-3).** A host work item is created only under the delivery's `_gate` while the delivery is open, with that message's token. If the token is cancelled before the item runs, the delegate never runs.

**I-4 Bounded retention (ADV4-2).**
- A host work item references only (the unpack delegate, the packed text, the token).
- Its release continuation references only its reservation handle.
- Nothing reachable from host code references the `Delivery`.

**I-5 Budget.** A delivery's result is set no later than its budget timer, the caller's cancellation or the shutdown. Unchanged.

**I-6 Floor and start rule.**
- A message starts only if e ≤ B − F, where e is the time since the budget started, read once and clamped to [0, B].
- Its share is at least F.
- So every started message has at least F before it is cut.

**I-7 Share (the owner's formula, with F as an extra floor).**
- For take position p (0-based) of the n messages handed to the workers:
  `share = min(B − e, max(S(n), F, (B − e) / ceil((n − p) / 4)))`, with S(n) = B / ceil(n/4) the static share.
- "remaining" = n − p: this message plus every one not yet taken. Held-back messages are excluded.

**I-8 Fast failures never starve the delivery.** A delivery of at most 100 messages whose failures each cost less than τ starts every message before the cutoff, because ceil(n/4)·τ ≤ 25τ = B − F.

### The slow memory

**I-9 What is written.**
- A message whose host call ran and did not open is **struck** iff budgetStart ≤ start ≤ end and end − start ≥ τ. "end" is when its outcome was decided: its own failure, its share's cut, or the budget's end.
- A message that opens is **forgotten**.
- Never written for:
  - a capacity refusal;
  - a message not started;
  - a message that is not valid UTF-8 or is empty;
  - a message running when the caller cancelled or the shutdown came.

**I-10 What is keyed.**
- Partition = (mediator DID, mailbox DID). Both come from the host's call.
- Entry = SHA-256/128 over (partition, the attachment id's exact UTF-8 bytes).
- Nothing a sender writes enters a key or decides a write: not the `skid`, `from`, the bytes or the sender DID. Writes are decided only by our timers, readings and outcomes.

**I-11 Bounded.**
- At most R partitions × Q entries.
- Inside a partition, the least recently *seen* entry is evicted, ordered by a sequence counter, not a clock.
- Whole partitions are evicted least recently used.
- Each operation is O(Q + R) under one leaf lock.

**I-12 Fail open on clocks.**
- An entry holds a message back only while struckAt ≤ now < struckAt + backoff(strikes), with backoff(k) = min(Cap, T0·2^(k−1)).
- A reading below struckAt counts as due. A clock step can cost an extra opening; it can never lock a message out.

**I-13 Held back.**
- A held-back message gets its failure before any worker starts.
- It takes no reservation, runs no host code and is never acknowledged.
- Shares are sized without it.
- A delivery made only of held-back messages returns at once, with no timer.

**I-14 The sender key never over-attributes.**
- The named partition is `DidSubjectOf(skid)`, and only when the protected header's `alg` is ECDH-1PU+A256KW and `skid` is present (read with `JweParser.PeekRecipients`, the call Core makes).
- Otherwise the message is anonymous: anoncrypt, `apu`-only, unreadable, or anything else.
- Core resolves exactly `DidSubjectOf(kid)`, so a lookup charged to S resolves S.

### The live stream

**I-15 No reading comparisons (ADV4-4).** Every "due" decision is the fired flag of an alarm the stream armed (a `TimeProvider` timer). There is no `GetElapsedTime` comparison anywhere in the stream.

**I-16 One predicate.**
- `WaitAsync` returns without awaiting iff `NextAction() != None`, the same function the loop dispatches on.
- Every action changes the state that made it actionable, so the loop cannot spin.

**I-17 R1-1 kept.** The cycle alarm is armed only at a drain's end or after a failure, never while draining.

**I-18 The run (ADV5-3).**
- The failure run (the count and the give-up alarm, RequestTimeout + 30 s from the run's first failure) is reset by:
  - a drain's end;
  - a delivery (drain round or push) with at least one new entry;
  - an accepted acknowledgement.
- A retryable failure ends the stream only after the give-up alarm has fired.

**I-19 The drain's end (ADV5-4).**
- A drain round whose every entry is held, or already yielded as a failure in this drain, ends the drain.
- The per-drain set holds 128-bit hashes. It is bounded by (50 rounds + 50 pushes) × 10 and cleared at each cycle's start.

**I-20 One alarm per arming.**
- Each arming makes a new alarm and disposes the one it replaces.
- A callback only sets its own flag and pokes the wake source.
- A late callback of a replaced alarm changes no decision.

### Fetch

**I-21.** `FetchAsync` keeps no state across calls apart from the slow memory and the duplicate filter.

**Locks.**
- `Delivery._gate` protects the delivery's indexes, the closed flag, the outcomes and the start readings. Only work-item creation happens inside it.

## Decisions (architect's proposals, reconciled; all ours unless labelled)

- **D-1 Isolation key (ours).**
  - The key is (mediator, mailbox, `DidSubjectOf(skid)`), named only for ECDH-1PU with a `skid`; otherwise one anonymous partition per (mediator, mailbox).
  - Why `skid` cannot be used against an honest sender: junk that names S resolves S's own DID, then fails decryption without S's key. It costs S's partition only what S's own lookup costs.
  - An ECDH-ES envelope with a forged `skid` goes to the anonymous partition, so an anoncrypted message cannot charge a slow signer's lookup to S.
  - Rejected:
    - keying on `skid` whatever the algorithm (that spoof);
    - decoding `apu` (it would need a second header parser, a parser differential);
    - per-mailbox only (it fails the ADV2-2 acceptance).
  - Residuals: R-1 (Sybil) and R-2 (the anonymous partition).
- **D-2 Back-off (ours).**
  - T0 = 30·B (10 min) and Cap = 180·B (1 h). Both scale with `UnpackTimeout`, as the learning time does.
  - T0 outlasts learning at our mediator's quota (100 per grant): for a fetch loop with limit ≥ 4 learning takes about 500 s, and for the stream at the default lease about 373 s.
  - Cap bounds how long a wrongly-remembered honest message waits.
- **D-3 Memory bounds and key (ours).** Q = 256 per (mediator, mailbox) partition (2.5× our quota) and R = 256 partitions; about 4 MB worst case.
  - **The owner's key is "(mailbox DID, the mediator's attachment id)". We add the mediator DID to it.** Ids are "unique to the mediator" (3.0 L170), so another mediator could otherwise write an honest mediator's ids on slow junk.
  - Per-partition eviction means a hostile mediator's id churn evicts only its own partitions.
  - What an eviction costs: one more opening of that message at its next delivery.
  - What a restart costs: one more opening of each remembered message.
  - Rejected: one global LRU (churn would evict other tenants' entries).
- **D-4 C and P (ours).**
  - C = 64 = 16 live streams × 4. That is the honest peak with no refusals, and it bounds the host calls that can be held. Main bounds only let-go calls (16) and leaves in-flight calls unbounded.
  - P_named = 4 = `FetchConcurrency`: one delivery never refuses an honest sender in its own partition.
  - P_anon = 16: no worse than today's container-wide 16, and now scoped to the mailbox.
  - All are reservations.
- **D-5 Floor F = B/4 (ours, within the owner's formula).**
  - The share stays "never below the static share": F raises the floor only for deliveries of more than 16 messages.
  - Without F, a delivery of 100 honest senders whose DIDs take 2 s gives each 0.8 s, and every one would be remembered as slow.
  - Note: `ADV3_3` puts the honest message *first*. The owner's formula alone gives it 0.8 s; F gives it 5 s, and it opens. A new test pins the formula itself, with the honest message last.
- **D-6 τ = (B − F)/25 (ours).**
  - A message that failed after costing at least τ is remembered too. Otherwise a sender whose DID resolves just inside its share and then fails decryption costs a share at every redelivery and is never remembered, which leaves ADV3-6 open.
  - τ is the largest value for which I-8 holds at limit 100.
- **D-7 Refusals fail at once and are not remembered (ours).**
  - A message that cannot reserve (C or P full) fails at once with "unpack capacity exhausted", is not acknowledged, and comes back.
  - Rejected: waiting for a slot. A waiting worker brings back same-delivery starvation and adds a wait queue.
- **D-8 Attachment ids compare exactly (ours),** as `DeliveryReader` and our mediator already compare them. Case folding could merge two distinct opaque ids and hold back an honest message. Message ids (the duplicate filter) still compare ignoring case.
- **D-9 Error texts (ours, D7: our request id only, never a wire value).**
  - Held back (`TimeoutException`): "…was not opened: it was slow to open when it was delivered before, and it is not opened again until its pause ends. It was not acknowledged."
  - Capacity (`TimeoutException`; the text keeps "unpack capacity exhausted"): one variant for the partition, one for the container.
  - `OutOfShare` and `OutOfTime` keep their texts.
- **D-10 No public API (ours).** T0, Cap, F, τ, C, P, Q and R are internal constants derived from `UnpackTimeout`. No new option.
- **D-11 The stream decides "due" by alarms (ours; the owner's "simplify" direction).**
  - A clock step now costs nothing: no early cycle, and no postponement.
  - The ADV3-5 and ADV5-1 regression tests change their expected counts toward fewer cycles. Their property, "no storm, no postponement", is kept.
- **D-12 Give-up stays time-based (ours):** RequestTimeout + 30 s from the run's first failure, through an alarm. ADV5-2's documented rule is unchanged.
- **D-13 An honest but slow sender, with junk carrying its `skid` (ours; the coordinator's case).**
  - **The case:** S's DID takes 2–5 s to resolve, and junk names S in its `skid`.
  - **Lookups are not shared across messages.** Core's per-unpack key context keeps no cross-message state, by design. The client does not wrap the host's resolver either, so the design works the same with or without a resolver cache.
  - **What bounds the cost instead:**
    - P_named holds S's lookups at most 4 at a time per (mediator, mailbox), which also caps how much load the junk can put on S's own host.
    - Each junk message costs at least τ, so it is struck after one opening and held back for T0. So each junk message costs one lookup per back-off period, never one per delivery.
  - **Why S's real message is never refused for its partition.** Inside one delivery, a worker gives back the reservation of a host call that has ended before it takes its next message. This is an exactly-once release, shared with the continuation. So the four workers can never find S's partition full of their own finished calls. Only another delivery's calls for the same (mediator, mailbox) still running, or host calls let go and still running, can fill it.
  - **The bound.** S's real message is opened within the acceptance bound: its junk is learned at least as fast as never-resolving junk.
  - **What remains is R-3:** while the flood lasts, an S slower than its share is cut.
  - **Rejected:** a client-level single-flight lookup per DID. It would mean either a cross-message cache of key results (against Core's no-cross-message-state rule for key evidence) or wrapping the host's resolver. Neither is needed for the bound.

## Acceptance bound (architect's figures; QA verifies)

**Assumptions:**
- N is the number of never-resolving messages in front, N ≤ min(quota − 1, Q). "Any number" is 99 at our mediator, and up to 256 at a mediator without a quota.
- Every message N is new to the client.

**Fetch loop at a leasing mediator.**
- Bound: T_reach ≤ ⌈N / min(limit, 16)⌉ · B of learning fetches, plus instant fetches over the remembered ones. In leases: T_reach / lease.
- Limit 4:
  - N = 16: about 80 s (1.3 leases at 60 s; 8 at a 10 s lease);
  - N = 31: about 160 s;
  - N = 99: about 500 s (8.3 leases).
- Limit 10:
  - N = 16: 40 s or less;
  - N = 31: about 80 s;
  - N = 99: about 200 s.
- One sender whose lookups never end: P refuses its 5th and later messages at once, so the honest message is reached within one learning fetch.

**Live stream at a leasing mediator.**
- About 10·max(1, ⌊lease/B⌋) messages are learned per cycle.
- At the defaults: N = 16 in cycle 1, N = 31 in cycle 2, N = 99 in about cycle 4 (about 6 min).
- With a 10 s lease: N = 99 in about 10 cycles. One re-learning happens, with a doubled back-off, still bounded.

**A mediator that does not lease.**
- Fetch reaches the honest message only within `limit` of the head. Otherwise the host discards with `AckAsync`, and the memory makes those fetches instant (no host code, no budget).
- The stream: at most 2 requests and one failure per held-back message per poll (ADV5-4).

## Residuals to document (replacing #96's known limits)

- **R-1:** an attacker with many sender DIDs can still fill the container's C when the host's resolver does not honour cancellation (ADV2-2 narrowed, not closed).
- **R-2:** anoncrypted, `apu`-only and re-wrapped messages share one partition (16) per mailbox.
- **R-3:** under a sustained flood of fresh slow junk, an honest sender slower than F is cut at F every time.
- **R-4:** more than Q messages queued per mailbox, or more than R (mediator, mailbox) pairs, thrash the memory (each costs one extra opening).
- **R-5:** a restart forgets the memory.
- **R-6:** a mediator that does not lease still needs the host to discard with `AckAsync`.
- **R-7:** a `recipientDid` filter mismatch is not remembered.
- **R-8:** up to C host calls may be held by host code that does not return.
- **R-9:** a forward clock jump can strike a fast failure once.
- **R-10:** the stream learns per cycle in proportion to the lease.
- **R-11 (ours, not an owner decision):** a stream whose requests keep failing does not give up while pushes keep bringing new messages.
  - Why: a push with a new message is progress, and progress resets the failure run (I-18).
  - Who is affected: a recipient whose mediator still pushes but refuses or drops its requests. Its stream keeps retrying instead of ending.
  - Bound: its request rate stays capped by the back-off (at most one cycle per 30 s at the longest back-off).
- **R-12 (ours, not an owner decision):** when a drain outlasts the mediator's lease, the messages it already reported as failures come back first, and a round made only of them ends the drain (I-19).
  - Why: a Message Pickup 3.0 `delivery-request` has no offset, so the client cannot step past messages the mediator keeps returning first.
  - Who is affected: a recipient with more messages that are slow to open than one drain can pass within a lease. Messages queued behind those wait one more `LivePollInterval`.
  - Nothing is lost: live mode stays on, and unacknowledged messages stay queued.
