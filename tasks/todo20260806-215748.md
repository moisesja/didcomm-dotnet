# Issue #73 — sample selector and core matcher disagree at truncation depth ≥ 2

Issue: https://github.com/moisesja/didcomm-dotnet/issues/73 (PR #69 follow-up)

## Verified diagnosis

- Core (`src/DidComm.Core/Protocols/ProblemReport/ProblemReport.cs`,
  `AnyLanguageAcceptable` + `ExtendsAtSubtagBoundary`) matches at **any** subtag boundary:
  preference `zh-Hant-TW` is satisfied by an offered `zh-Hant` (line 272–274) → no
  `bad-lang` report.
- Sample selector (`samples/10-ProfilesAndI18n/Program.cs`, `PickLanguage`, lines 332–355)
  truncates only to the **primary** subtag (`IndexOf('-')` → `zh-Hant-TW` → `zh`), so it
  misses a `zh-Hant` catalog entry and silently serves the default language.
- Divergence confirmed: exactly the #69 failure mode (core says "available", emitter can't
  honor it), one truncation level deeper.
- The bug is **latent in the shipped sample**: `BobsCatalog` is `{en, fr}` (no multi-subtag
  keys), so the runtime demo never hits depth ≥ 2 today. It bites anyone who copies the
  "reference selector" — which the core doc-comment (lines 209–214) explicitly blesses —
  into a richer catalog.
- Secondary latent mismatch found during review (opposite direction): core's `IsUsableTag`
  drops malformed tags (`en-`, `-en`, `en--GB`); the sample only skips whitespace. A
  preference of `en-` against catalog `{en}` makes core emit a report (unsatisfiable) while
  the sample truncates to `en` and happily serves it — spurious report alongside a served
  reply. Cheap to align in the same round.

## Risk assessment: LOW

- No shipped library behavior changes. The core matcher is correct and stays untouched;
  only its doc-comment changes. Edits land in a sample, tests, and XML docs.
- No wire format, crypto, envelope, or public API surface involved.
- The one genuine trap: the fixed selector must be exactly as broad as core and **no
  broader**. Truncate-and-exact-match at every subtag boundary, but run the broad-direction
  scan (catalog entry extends the request) against the **original** preferred tag only —
  applying it to truncations would serve siblings (`zh-Hant-TW` → truncate `zh-Hant` →
  broad-match `zh-Hant-HK`) that core correctly reports as unsatisfiable.

## Decision: fix the selector in place (issue option A)

Rejected option B (extract a shared helper into DidComm.Core): it guarantees agreement by
construction but adds public API surface (semver, docs, PublicApiCoverageTests) for a
MAY-level convenience the library deliberately keeps minimal — the core doc-comment even
tells callers needing real negotiation to do their own matching. Option A is the
minimal-impact fix; the agreement is pinned by tests instead of by construction.

## Review

Executed 2026-08-06, exactly per plan, one deviation noted below.

**Red-first demonstration.** Steps 2/4/5 (demo beat + tests) were applied *before* the
selector fix and the suite run: the transcript showed the issue's exact failure mode —
`Bad-lang report warranted = False` (matcher satisfied, no report owed) next to
`Reply to zh-Hant-TW — lang = en` (selector fell back to default). The two new core-side
tests passed pre-fix, confirming the core matcher was already correct and only the sample
selector was at fault.

**Fix.** `PickLanguage` now truncates one subtag at a time from the right (most specific
first), runs the broad-direction scan against the request as sent only (the sibling trap:
a truncated `zh-Hant` must not land on a `zh-Hant-HK` entry the matcher refuses), and
skips malformed tags under the matcher's own empty-subtag rule — closing the reverse
disagreement (spurious report + served reply) found during plan review.

**Environment finding (not a code issue).** The full suite initially showed 91
InteropTests failures; a clean-baseline run (git stash) showed the identical 91, all
`DirectoryNotFoundException` on the fixtures directory — the
`tests/DidComm.InteropTests/fixtures` **git submodule is not auto-initialized in
worktrees**. Fixed locally with `git submodule update --init`; no repo change needed
(CI already inits submodules per the Phase 6 changelog).

**Final state.** Full suite green: DidComm.Core.Tests 799/799, DidComm.InteropTests
272/272 (fixtures submodule restored 67 fixture-driven tests that could not run in the
stale environment). CHANGELOG updated under [Unreleased].

**Deviation from plan.** No separate checkpoint commit for the failing state — committing
red to a CI-gated branch trades bisectability for nothing; the red-first evidence is the
recorded pre-fix run above. Shipped as a single commit.
