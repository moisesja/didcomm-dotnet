# Fix #53 — Lazy `Utf8ByteCount` on `InboundMessageSnapshot`

## Context

Issue #53 (LOW-severity perf, filed from the PR #51 adversarial review): every successful
`UnpackAsync` eagerly computes `Encoding.UTF8.GetByteCount(plaintextJson)` in the
`InboundMessageSnapshot` constructor, an O(plaintext) scan paid even by consumers that never
read the byte count. The only reader is `ObserverDelivery`'s byte-budget admission.

Chosen remedy: **option 1 from the issue** — defer the byte count to first access. Registration
stays at the unpack boundary exactly where it is; the verified-at-unpack security binding from
PR #51 is untouched. Anti-churn goal: one tightly-scoped PR that satisfies the issue's
acceptance criteria line-for-line, with the predictable reviewer objection (thread-safety of the
lazy compute) pre-empted by a comment in the diff.

## Scope guard

- **Only** `src/DidComm.Core/Protocols/InboundMessageSnapshot.cs` changes in production code.
- **No** changes to `EnvelopeReader.cs`, `ProtocolDispatcher.cs`, or `ObserverDelivery.cs` —
  the registration site and consumption guard are load-bearing for PR #51's trust invariants.

## Plan

- [x] 1. Create branch `feat/lazy-snapshot-bytecount-53` off `main`.
- [x] 2. In `InboundMessageSnapshot.cs`:
  - Remove `Utf8ByteCount = Encoding.UTF8.GetByteCount(plaintextJson);` from the constructor.
  - Replace the auto-property with a lazily computed property backed by
    `private int _utf8ByteCount = -1;`:
    ```csharp
    internal int Utf8ByteCount
    {
        get
        {
            // Lazy: only ObserverDelivery's byte-budget admission reads this; the plain
            // unpack path must not pay an O(plaintext) scan (#53). Benign race by design:
            // GetByteCount is deterministic over the immutable PlaintextJson and int
            // writes are atomic, so concurrent first readers at worst recompute the
            // same value.
            var count = _utf8ByteCount;
            if (count < 0)
                _utf8ByteCount = count = Encoding.UTF8.GetByteCount(PlaintextJson);
            return count;
        }
    }
    ```
- [x] 3. Add `tests/DidComm.Core.Tests/Protocols/Dispatch/InboundMessageSnapshotTests.cs`
  (internals are already visible to Core.Tests — `ObserverDeliveryTests` exercises internal
  types directly):
  - **Laziness:** after `RegisterVerified` + `TryGetFor`, the private backing field
    `_utf8ByteCount` (read via reflection) is still `-1` — proving the unpack-only path never
    scanned the plaintext. Reflection guarded with a clear failure message if the field is
    renamed.
  - **Correctness:** first read of `Utf8ByteCount` returns
    `Encoding.UTF8.GetByteCount(plaintextJson)` for a payload containing multibyte characters
    (so byte count ≠ char count and the assertion is meaningful).
  - **Memoization:** after the first read, the backing field holds the value and a second read
    returns the same result.
- [x] 4. Run the full test suite (`dotnet test`). Acceptance requires all existing PR #51
  correlator/observer trust tests (cross-tenant reply rejection, snapshot immutability,
  byte-budget admission) to pass unchanged.
- [x] 5. Update `CHANGELOG.md` (perf entry referencing #53).
- [x] 6. Commit, push, open PR with `Closes #53`, body mapping the diff to the issue's three
  acceptance criteria.
