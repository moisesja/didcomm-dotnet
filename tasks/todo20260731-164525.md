**Trigger:** the README advertises a package version that predates every published release, contradicts
itself on Phase 6, and describes packages that will never exist. It is also where FR-DX-05 (the
≤ 25-line quickstart, MUST) lives, so the same pass closes an open requirement.

**Baseline:** `main` @ `9b6d428` (v1.4.0 published; PR #67 carries the 1.4.1 prep).

## Two decisions I need from you

### D1 — which branch

- **(a) A new branch off `main`, its own PR.** Keeps #67 a de-flake PR. Ships whenever it ships.
- **(b) Onto PR #67, releasing with 1.4.1** *(my recommendation)*. The Install section currently tells
  people a published library "has not been tagged/published yet — until then, build from source."
  That is wrong on nuget.org **today**, and 1.4.1 is the next thing out the door. Docs-only, so it
  cannot affect the packages.

### D2 — how far to take the quickstart

- **(a) README snippet only.** Fastest. FR-DX-05 says "a new developer can copy-run the quickstart
  unmodified" — I would verify it by building and running it once in a scratch project, then pasting
  it in. Nothing stops it drifting later.
- **(b) Snippet + `samples/01-Quickstart`** *(my recommendation)*. §14.3 defines sample 01 as exactly
  this quickstart, and the README is the drift-prone place for code. A real project means CI compiles
  it and the claim stays true. Costs one small project (~40 lines + README) and closes the first of
  the nine missing sample apps.

Everything below is common to either choice.
