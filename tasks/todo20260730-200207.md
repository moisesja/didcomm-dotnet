# Issue #61 — Mirror `RecipientAddressing` onto `InboundMessageSnapshot` / `InboundObservation`

## Context

Follow-up to #59/#60. The advisory FR-CONSIST-04 outcome (`RecipientAddressing`: `NotEvaluated` / `Addressed` / `NotAddressed`) is surfaced only on the facade `UnpackResult`. Consequences (from the issue):

1. **Observer-only applications can't see the warning** — `IProtocolObserver` receives an `InboundObservation`, which lacks the value, and the observer seam is the *only* consumer on the no-handler, loop-drop, and handler-failure paths.
2. **The public value can go stale / be laundered** — `Message` is mutable and the record `with`-clone copies the enum, so the facade value can describe addressing the current message no longer has. #56 gave the `VerifiedKeyBinding` family a snapshot backstop for exactly this; `RecipientAddressing` has none.

Fix: thread the value the same way #56 threaded the bindings — internal `UnpackResult` → `InboundMessageSnapshot.RegisterVerified` → `InboundObservation` (`public get` / `internal init`, additive, binary compatible) — with every synthetic/fallback/mutated path yielding `NotEvaluated`.

Verified facts (explored, current HEAD):
- `recipientAddressing` is computed at `EnvelopeReader.cs:171` and is in scope at the `RegisterVerified` call (:272–284) — both inside the `EnvelopeKind.Plaintext` case, the single place snapshots are registered and the final result is built.
- `InboundMessageSnapshot.cs` and `InboundObservation.cs` both already have `using DidComm.Facade;` — the enum is directly usable.
- Only production construction sites: `RegisterVerified` (EnvelopeReader.cs:272), `CreateFallback` (ProtocolDispatcher.cs:133), `InboundObservation.FromUnpackResult` (:70) and `FromSnapshot` (:112) — all four must be touched (lesson L-043: one hardened path is a half-fix).
- ApiCompat = SDK package validation (Directory.Build.props:41–42, baseline 1.3.0). Additive non-positional property is clean; positional ctors untouched (L-035).
- Bonus invariant (validated): because the observation never reads `received.RecipientAddressing`, a `with`-clone of a *real* result (same `Message` reference) still resolves the snapshot's value — a laundered copy of the facade enum is ignored on every observation path. The single-sourcing from the snapshot **is** the anti-laundering guarantee; `CreateFallback` must uphold it too by refusing the facade result's claimed value.
