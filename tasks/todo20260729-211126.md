### Findings posted

1. **Blocking — config-amplified unauthenticated CPU work and residual timing leakage.**
   `SnapshotOwnIdentifiers` validates but retains raw identifiers, and
   `CheckRecipientAddressing` reparses every configured identifier for every inbound message.
   Per-message work therefore remains `O(|OwnIdentifiers|)`, allowing tiny unauthenticated
   plaintext requests to amplify CPU by the receiver's tenant-roster size. The sender does not
   know that roster size, contrary to the PR's timing claim.
2. **Missing security regression.**
   The test named `Recipient_addressing_checks_every_identifier_regardless_of_match_position`
   checks only final enum values. A short-circuit implementation passes all its assertions.
   The review requested an instrumented `to` enumerable plus a roster-independent scaling
   regression/reproducer.
3. **Non-blocking completeness gap.**
   `RecipientAddressing` is absent from `InboundMessageSnapshot` and `InboundObservation`, so
   observer-only applications cannot consume the warning on all dispatch outcomes; the public
   value can also become stale after message mutation or result cloning.

The requested implementation direction was to normalize and deduplicate own DID subjects once
at client construction into an immutable/frozen set, then fully scan the bounded attacker-authored
`to` input against that set without early exit.
