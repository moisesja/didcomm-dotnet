## Invariants (D-1..D-5 extended to direct push; D-6, D-7 new)

- **D-1 The store decides what is pushed, live or direct.** Each push takes the grant's next record from the store at the moment it pushes it (`PickupCoordinator.TakeNextAsync`: due, unexpired, unleased, not passed over, unmarked, oldest first; registration checked at delivery time). Nothing else names a record to push.
- **D-2 Wake-ups, not jobs.** A stored, already-due message wakes its grant when the grant has a live target, or always when direct push is on. A wake-up carries only the grant DID. No due-time scheduler (D2).
- **D-3 One operation per grant until it settles.** Unchanged: at most one POST in flight per grant.
- **D-4 Bounded.** Unchanged: `PushConcurrency` workers; at most 2 × `PushConcurrency` unsettled operations; `MaxDeliveryBatch` pushes per run, then yield; grants served in turn; one record held per operation.
- **D-5 A push names what it took.** A direct push takes under its own lease and ends it exactly once, never cancelled: `AcknowledgeAsync` after a 2xx; `ReleaseAsync(leaseId)` after an attempted send (mark kept); `ReturnUnsentAsync(leaseId)` when the send was never attempted (mark cleared).
- **D-6 At most one push attempt per message, kept on the record.** The store sets the push mark in the same step as any push's take (live or direct). The attempt is spent the moment the mediator calls the session or the transport; only a definite "not sent" clears the mark.
- **D-7 Where and how a direct push goes.** Only the endpoint the host's `IRecipientEndpointDirectory` returns for the grant, read before the take; never anything the message carries. Absolute `http`/`https` only, accepted by the transport's `AllowedSchemes`, passed by the outbound guard before the take and on every connection. One send per attempt on the mediator's own transport instance: no retry, a breaker that never opens, 307 followed up to `MaxRedirectHops` with every hop vetted, 301/302/303/308 never followed (OD-1). Live wins: each push checks the live session first.

## Design (calls and reasons)

### 1. Published-API question: settled, no public change to any published package

- **Mechanism.** The HTTP transport's circuit breaker lives in each `HttpDidCommTransport` instance's Polly pipeline (`HttpResiliencePipelineFactory.Create(_options)` in the constructor); nothing about it is shared or static. So `DidComm.Mediator` (unpublished) builds one private instance through the existing public constructor `HttpDidCommTransport(IHttpClientFactory, IOptions<HttpTransportOptions>, ILogger<HttpDidCommTransport>?)`, over the container's `IHttpClientFactory`. The transport always creates the named client `"didcomm"`, so the push uses the host's `UseHttpTransport` handler: the connect-time outbound guard pin, `AllowAutoRedirect = false`, direct by default, `TrustedProxy` only when the host names one (#88 comment 6984801690: "through the transports … never … an HTTP client of its own").
- **The options copy** (all 9 public settable properties named; a reflection test fails when a new one appears): `MaxRetryAttempts = 0` (the factory then adds no retry strategy); `CircuitBreakerFailureThreshold = int.MaxValue` (Polly 8.9.0 accepts `MinimumThroughput` in [2, int.MaxValue]; the breaker can never open); `MaxRedirectHops` = the host's value (OD-1: the transport's existing 307 limit); `OutboundEndpointPolicy` = the host transport's, else `DidCommOptions.OutboundEndpointPolicy`, else a default (the same resolution `UseHttpTransport` uses); `TrustedProxy`, `AllowedSchemes`, `RequestTimeout`, `CircuitBreakerOpenDuration`, `RetryBaseDelay` copied.
- **The instance is never registered as `IDidCommTransport`**, so the host's own sends never use it, and the push never uses the host's.
- **Pre-send checks, before the take** (what `SendPackedAsync` does, with public API): absolute URI; scheme `http`/`https` only (also excludes `didcomm:transport/queue`, ws, wss); `transport.CanHandle` (`AllowedSchemes`); `new OutboundEndpointGuard(DidCommOptions.OutboundEndpointPolicy).Validate(endpoint)`. Media type is `application/didcomm-encrypted+json` (the mailbox holds JWEs only, OD-1 of #100). Every later hop is vetted by the transport itself (connect-time pin, or the per-hop destination check through a proxy).
- **Refused at start-up**: direct push on without `UseHttpTransport()` (the named client would otherwise be a default handler with the environment proxy and no pin), without an `IRecipientEndpointDirectory`, or with an invalid `TrustedProxy`.
- **Packaging.** One new `ProjectReference` `DidComm.Mediator` → `DidComm.Transports.Http`. Transports.Http grants `InternalsVisibleTo` only to `DidComm.InteropTests`, so this is not a friend edge: it packs as a minimum-version dependency, and `ShippedAssembliesListTests`' pinned edges do not change. Only public API is used, which package validation keeps binary-stable across minors, and RELEASING ships every package in lockstep. Transitive additions for a mediator host: `DidComm.Transports.Http` itself plus Polly 8.9.0 and Polly.Core 8.9.0 (Microsoft.Extensions.Http was already transitive through NetDid.Extensions.DependencyInjection; checked by an assets diff, engineer C). `dotnet pack` writes `<dependency id="DidComm.Transports.Http" version="…">`, a minimum version. The CHANGELOG names the new dependency.
- **Rejected (ours):** an internal Core overload of `SendPackedAsync` taking a transport (not public, but a code change in a published package); a new public `SingleAttempt` flag (a public change, refused by the brief).

### 2. The attempt mark: #143's mark, reused unchanged (ours)

- A direct push takes its record under `new MessageLease(Owner: null, now + LeaseTimeout) { LivePush = true }`. The mark (`QueuedMessage.LivePushReturned`) is set by the store in the same step as the take, judged by the request's `Now`, survives release, lease expiry and restarts, and is cleared only by `ReturnUnsentAsync`/`PassOverAsync` from the same lease.
- Its meaning widens to "a push, live or direct, took this record and has not said it was not sent: it is for a `delivery-request` only". That is OD-3's rule ("waits until the recipient asks for it") and OD-5's ("only … 'not sent', or no attempt at all, keeps a message eligible") applied to both pushes. FR-PICK-06 is untouched (direct push takes with `AfterSequence = null`).
- **No store contract change.** A host store implementing #143's contract needs no code change. Only the docs of `IMessageStore` (the mark bullet), `MessageLease.LivePush` and `QueuedMessage.LivePushReturned` widen to "a push lease: over a live connection or to the recipient's registered endpoint; a push lease may have no owner". A store contract test covers a push lease with a null owner.
- **Names: renamed (owner decision OD-4 for #110).** `MessageLease.ForPush` and `QueuedMessage.PushTaken` (were `LivePush` / `LivePushReturned`). The mediator builds every push lease through one helper (`PickupCoordinator.PushLease`).
- The #109 spike's three notes hold by construction: the store judges by the caller's `now`; nothing new is added to the public in-memory store; with directory check → take + mark → send, a revoke-and-purge that lands before the take leaves nothing to take.

### 3. The direct step

- **Directory:** `public interface IRecipientEndpointDirectory { ValueTask<Uri?> FindAsync(string grantPeerDid, CancellationToken ct); }` in namespace `DidComm.Mediator`. Keyed by the grant's peer DID (ours): a per-recipient-DID lookup could only happen after the take, and "no endpoint" would then hand back and re-take the same head record at every wake (ADV-5's shape). A throw means no endpoint (rate-limited Warning, exception type only); cancellation propagates (deadline).
- **`PickupCoordinator.PushNextDirectAsync(grantPeerDid, directory, sender, ct)`**, in this order:
  0. `await Task.Yield()` so the push deadline governs synchronous host code.
  1. `ct.ThrowIfCancellationRequested()`.
  2. `endpoint = await directory.FindAsync(grantPeerDid, ct)`; a throw → `NoEndpoint`, nothing taken.
  3. Endpoint checks (section 1) → `NoEndpoint`, nothing taken. The log carries the reason only, never the URI or the DID.
  4. `lease = PushLease(now)`; `TakeNextAsync(grantPeerDid, lease, afterSequence: null, now, ct)` (marks in the same store step; contract checks; registration re-check) → `Removed` / `Empty`.
  5. Deadline passed → given back as unsent (mark cleared), rethrow. Expired at a fresh clock reading → given back as unsent, `Expired`, and the operation goes on to the next record (the store will not hand it out again).
  6. One send of the stored payload to the endpoint read in step 2 (a change in the directory applies from the next push).
  7. 2xx at the end of the chain → `AcknowledgeAsync` (`CancellationToken.None`) → `Delivered`. Any non-2xx, any 3xx other than a followed 307, a hop past the bound, a guard refusal, a 307 without a usable `Location`, or a transport fault → `ReleaseAsync` (mark kept) → `NotDelivered`. Cancellation during the send → `ReleaseAsync` (mark kept) → rethrow. Logs carry the status or the exception type, never `ex.Message` (it names the URI) or a `Location`.
- **Dispatcher, per push:** `PushNextLiveAsync` first; only on `NoSession`, and only when direct push is on, `PushNextDirectAsync`, under the same per-push deadline.

| Step | Counter (`didcomm.mediator.push.outcomes`) | Operation | Record |
|---|---|---|---|
| Delivered | `Pushed-Direct` (new) | next record | removed |
| NotDelivered | `Push-Failed` | ends, no yield; the recipient's direct pushes pause for 2 × `PushTimeout` (the churn call; first built as "next record") | marked; `delivery-request` only |
| Expired | none | ends, no pause (first built as "next record") | given back unsent; expired, never handed out again |
| Removed | `Push-Skipped-Unregistered` | next record | removed by id |
| NoEndpoint | `Push-Skipped-NoEndpoint` (new), first push of an operation only | ends | none taken |
| Empty | none | ends | — |
| deadline | `Push-Failed`; on the direct branch the recipient's direct pushes pause for 2 × `PushTimeout` (a live deadline keeps the shared cooldown) | ends | released (kept marked) once the call ends; given back unsent if the send never started |
| fault (store, sender, endpoint check) | `Push-Failed`; direct pause | ends | given back |
| LiveSession (QA1-2) | none | next push (goes live) | none taken |
| direct pause running | `Push-Skipped-Cooldown`, once per operation | ends (the live step still runs) | none taken |

- **First built as "not delivered → next record" (ours); replaced by the churn call:** after QA round 3 reopened the guards built around it (QA3-1..3), any direct push that does not deliver ends its run and pauses that recipient's direct pushes for 2 × `PushTimeout`, whatever ended it. Narrowed property: a refused message never holds up later ones beyond the pause and is never sent again; the ones behind it go at the first wake-up after the pause (until the next refusal), or by pickup. Egress ≤ (`MaxRedirectHops` + 1) × accepted bytes.
- **Sink:** `MediatorForwardSink.HandToPush` wakes a due message's grant when direct push is on, or when the grant has a live target (unchanged when off).
- **Lease (ours):** no owner (no connection, so a session close never ends it), expiry `now + LeaseTimeout`, as for a live push: a concurrent `delivery-request` stays off the record during the POST.

### 4. Options, DI, validation

- `MediatorOptions.DirectPush` (bool, default `false`), copied in `Effective()`. It is read from the settings in effect, like `PushConcurrency`; nothing is registered conditionally, so the `EnableV2`/`EnableV4` mismatch class cannot arise.
- `AddMediator()` always `TryAdd`s the internal `DirectPushSender` factory; nothing builds it, or resolves the directory, while direct push is off (a test counts factory calls).
- With direct push in effect: no `IRecipientEndpointDirectory` → `InvalidOperationException` when the dispatcher is built (start-up); `MediatorHostedService.StartingAsync` resolves the sender (no HTTP transport or a bad `TrustedProxy` fails start-up); the "ready" line says direct push is on. Outside a generic host the same checks run lazily at the first push.
- Directory constructor rule, as for stores: no protocol dispatcher, handler, `DidCommClient`, queue, sink or dispatcher.
- **Rewrap:** first built as a refusal of `DirectPush` with `RewrapMode.ReanoncryptToNext`; dropped by owner decision OD-3 for #110 (section 5).

### 5. Rewrap and the receiving end (owner decision OD-3 for #110)

- In rewrap mode the stored payload is the mediator's own anoncrypted `forward` addressed to the recipient. routing.md L67: "Normally, the payload attached to the `forward` message received by the mediator is transmitted directly to the receiver with no further packaging. However, optionally, the mediator can attach the opaque payload to a new `forward` message (appropriately anoncrypted), which then acts as a fresh outer envelope for the second half of the delivery." L71: "Rewrapping mode is invisible to senders, but mediators need to know about it, since they change their behavior as a result. Receivers also need to know about it, because it causes them to receive a double-packaged message instead of a singly-packaged one. The outer envelope is a `forward` message where `to` is the receiver itself."
- Until now a plain didcomm-dotnet endpoint (`MapDidCommEndpoint`, published DidComm.AspNetCore) answered 202 without opening such a forward, so a 2xx removed a message nobody read — with our direct push, and with any rewrap-mode mediator delivering to our endpoint.
- First built (ours) as a start-up refusal of the combination; the owner chose instead to fix the endpoint in this PR (OD-3). ### 8. Residuals (stated, not closable by construction)

1. A tarpit holds one worker at most once per pause, whatever ends the stall (the deadline, the transport's or the client's own timeout); K tarpits ≥ W workers delay healthy pushes by up to ceil(K/W) × `PushTimeout`. Nothing is lost; pickup always works.
2. A host store that drops the mark loses the one-attempt guarantee: such a record is re-pushed at most once per pause, and the ones behind it wait for pickup (a marked record handed to a push is refused, fail-closed). A store that judges expiry by a lagging clock costs one take per wake-up. A crash between take and send leaves the record marked: pickup only.
3. At-least-once: a deadline or a dropped connection after the receiver handled the POST, a 2xx whose removal fails, a POST that outlives its lease. Recipients de-duplicate by message id (already documented).
4. A revoke-and-purge or acknowledgement that lands after the take's registration check, or live delivery turned on after the direct take, lets the in-flight POST complete (as for live push and pickup): at most a duplicate under at-least-once.
5. A host that replaced the `"didcomm"` handler owns its connect, redirect and proxy behaviour (as for every send of that host).
6. A directory that ignores cancellation keeps its operation unsettled (the D-4 residual).
7. OD-1: up to `MaxRedirectHops` + 1 POSTs per message (6 at the default), the extra ones to public hosts the registered endpoint chooses, each vetted.
8. Push-only recipients still pick up: a refused push and a delayed message wait for the next wake-up or pickup (D2, OD-2).

### 9. Live interop cell (ours): not added

The push POSTs the stored JWE unchanged, with the bytes and media type any direct sender posts, so it adds no interop surface. A cell against our own mediator would re-test our own transport over the network, which the in-process suites do deterministically.

## CI on the PR

- **Windows, `MediatorNextOracleAdvTests`.** The timing test compares the median time of five forward
  classes against a forward for a known `next`. It failed on windows-latest with a ratio of 3.56 for
  a self-addressed layer around a forward for an unknown `next` (bound 3.0). Ubuntu passed.

  layer's opening, its result or its refusal, against that layer's own unpack result

  path and its drops are unchanged. O-1 is fixed instead of documented. Tests:
