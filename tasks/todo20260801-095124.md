## Stated defaults (approval of this plan authorizes them)

- **D1 — fixtures submodule (§13.3):** I will create the public repo
  `moisesja/didcomm-dotnet-fixtures` via `gh`, push the restructured fixture set (spec +
  harvested + our published vectors), and wire it into this repo as a git submodule at
  `tests/DidComm.InteropTests/fixtures` (CI checkout gains `submodules: true`). This is the
  PRD-mandated layout and is overdue Phase 0 debt. Fallback if repo creation is vetoed:
  in-tree restructure matching the same layout, submodule split deferred.
- **D2 — STOMP (FR-TRN-12, MAY):** implement a *minimal, opt-in* STOMP 1.2 subset on the
  WebSocket transport (CONNECT/CONNECTED/SEND/MESSAGE/DISCONNECT frames, content-type
  `application/didcomm-encrypted+json`), off by default. No broker features.
- **D3 — live-harness verification limits:** the nightly workflow (FR-IX-04/05/08) is written,
  lint-checked, and its scripts are exercised locally against the pinned `didcomm` Python
  package where possible; the JVM leg is only fully provable on the first nightly run. The PR
  will state this honestly.
- **D4 — NFR-07 targets:** benchmarks run locally on this Mac; actual numbers recorded in the
  benchmark README. "Reference HW" P99 targets are reported, not CI-gated.
- **D5 — coverage-gate policy (FR-DX-01):** coverage = a public member is referenced from the
  IL of at least one sample assembly (Mono.Cecil scan). Exemptions, documented in the test:
  enum members and `const` fields (inlined by the compiler, undetectable in IL),
  compiler-generated members, `[Obsolete]` members. Types must appear as TypeRefs; methods /
  ctors / property accessors / events as MemberRefs.
